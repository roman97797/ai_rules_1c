# /changed-objects-grouped — список изменённых объектов по типам

Выводит список изменённых объектов конфигурации, сгруппированный по типу, **с точностью до модуля**. Процедуры и функции в список не попадают. Видно, в каком модуле правка: модуль объекта, модуль менеджера, модуль формы.

## Формат

```
## Изменённые объекты

**Документ**
1. Документ.Имя.МодульОбъекта
2. Документ.Имя.МодульМенеджера

**Обработка**
3. Обработка.Имя.МодульОбъекта
4. Обработка.Имя.ИмяФормы.МодульФормы

**Общий модуль**
5. ОбщийМодуль.Имя.Модуль
```

- квалифицированное имя: тип, объект и модуль (`Документ.Имя.МодульОбъекта`, `Обработка.Имя.ИмяФормы.МодульФормы`, `ОбщаяФорма.Имя.МодульФормы`, `ОбщийМодуль.Имя.Модуль`);
- новый объект без собственного модуля остаётся строкой `Тип.Имя`;
- сквозная нумерация;
- заголовок группы — только для типов, у которых есть изменения;
- без пояснений и путей к файлам.

## Аргументы

`$ARGUMENTS` может содержать:

| Аргумент | Назначение |
|---|---|
| `--staged` | только staged-изменения |
| `--base <ref>` | база сравнения, по умолчанию `HEAD` |

Номер задачи не фильтрует список: берутся все объекты из git diff рабочей копии.

## Шаги

1. Разобрать `$ARGUMENTS`: `--staged`, `--base`.
2. Запустить из корня репозитория:

   ```powershell
   powershell.exe -NoProfile -File content/skills/changed-objects/scripts/list-changed-objects.ps1 -Grouped -IncludeUntracked [-StagedOnly] [-Base "<ref>"]
   ```

3. Вывести пользователю stdout скрипта как есть. Если скрипт написал `Изменений не найдено.` — этой строки достаточно.

## Когда вызывать

По `/changed-objects-grouped` и когда пользователь просит список изменённых объектов без детализации до процедур.

Попроцедурный список остаётся у `/changed-objects`.
