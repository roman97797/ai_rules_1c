# /changed-objects — список изменённых объектов

Выводит нумерованный список квалифицированных имён изменённых объектов и методов **без описаний**.

## Формат строки

```
1. Документ.Имя.Реквизит
2. Документ.Имя.Процедура()
3. Документ.Имя.ИмяФормы.МетодФормы()
4. ОбщийМодуль.Имя.Функция()
5. WebСервис.Имя.Метод()
```

- реквизиты / элементы метаданных — **без** `()`
- процедуры и функции — **со** `()`
- модуль объекта — `Документ.Имя.Метод()`; модуль формы — `Документ.Имя.ИмяФормы.Метод()`
- без пояснений, только список

## Аргументы

`$ARGUMENTS` может содержать (в любом порядке):

| Аргумент | Назначение |
|---|---|
| число (например `44868`) | фильтр по номеру задачи в маркерах `// ++ ЗлобинР #NNNNN` |
| `--staged` | только staged-изменения (`git diff --cached`) |
| `--base <ref>` | база сравнения (по умолчанию `HEAD`; пример: `--base main`) |

## Шаги

1. Разобрать `$ARGUMENTS`: номер задачи, `--staged`, `--base`.
2. Запустить скрипт из корня репозитория:

   ```powershell
   powershell.exe -NoProfile -File content/skills/changed-objects/scripts/list-changed-objects.ps1 [-Task "<номер>"] [-StagedOnly] [-Base "<ref>"]
   ```

3. Вывести пользователю **только** нумерованный список из stdout скрипта — без преамбулы, без «Files changed», без пояснений.
4. Если список пуст — одной строкой сообщить, что изменений не найдено, и указать фильтры (задача / base).

## Когда вызывать

- по запросу пользователя (`/changed-objects`, `/changed-objects 44868`);
- вручную, когда нужен список изменённых объектов для проверки, отчёта или выборочного контроля diff.

## Ограничения

- Процедуры определяются по маркерам доработки (`// ++ ЗлобинР #…`, `// {ЗлобинР}#…`, `// +++ COMPANY; …`) и по git diff.
- Из XML извлекаются добавленные реквизиты (`<Name>…</Name>` в diff); прочие изменения метаданных дают только корневой объект (`Документ.Имя`).
- Не сканирует бинарные CF/CFE — только файловую выгрузку в репозитории.
